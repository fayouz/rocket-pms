Toutes les routes demandent un utilisateur connecté (jeton JWT) ou une application externe (`Authorization: Bearer rpm_…` et `X-Impersonate-User`). Envoyer `Accept: application/json`.

| Méthode | Route | Rôle |
|---|---|---|
| GET | `/api/properties` | Logements |
| GET · PATCH | `/api/properties/{id}` | Un logement ; modification (nom, couleur) : administrateur |
| POST | `/api/properties/sync` | Crée les logements depuis Lodgify (administrateur) |
| GET | `/api/properties/{id}/bookings` | Réservations (60 derniers jours et à venir) avec leur code clavier |
| GET | `/api/properties/{id}/bookings/{bookingId}/pricing` | Valeur et détail du prix |
| GET · POST | `/api/properties/{id}/bookings/{bookingId}/conversation` | Conversation ; réponse `{"text", "messageId": "<uuid>"}` |
| GET | `/api/places` | Lieux de Rocket Place (administrateur) |
| PUT · POST | `/api/properties/{id}/place` | Lie le logement à un lieu `{"placeId": "<uuid>" \| null}` · crée un lieu depuis le logement (administrateur) |
| GET | `/api/properties/{id}/locks` · `/api/locks` | Serrures du lieu · toutes (administrateur) |
| PUT | `/api/locks/{nukiId}` | Lieu ouvert par la serrure `{"place": "<uuid>" \| null}` (administrateur) |
| GET | `/api/properties/{id}/codes` · `/access-grants` | Codes des séjours à venir · accès du lieu (prévus au passage, `externalRef` = réservation) |
| POST | `/api/planning/run` | PMS_MANAGE : planifie codes et ménages de tous les logements liés à un lieu (fait aussi toutes les 15 min par le worker) → `{ranAt, properties: [{id, name, ok, grants, cleanings, error}]}` |
| POST | `/api/properties/{id}/access-grants/{grantId}/send` | Envoie le code à la serrure (action réelle, sur clic) · `/revoke` (administrateur) |
| GET | `/api/properties/{id}/domotique` · `/documents[…]` | Relais vers le lieu Rocket Place |
| GET | `/api/properties/{id}/stock` | Stock du lieu lu dans **Rocket Stock** `{items, levels}` ; `PATCH /stock/{levelId}` `{"level": "ok"\|"low"\|"empty"}` |
| GET | `/api/cast/properties/{id}` | Écran du logement pour **Rocket Cast** (jeton d'application, lecture) : charge utile de `/api/public/tv/{token}` + `propertyId`, `arrivals[]` et `departures[]` du jour `{firstName, arrival, departure, checkIn, checkOut}`, `version` (empreinte du livret et du voyageur présent / suivant) |

| GET | `/api/properties/{id}/timeline` · `/api/timeline` | Timeline **en lecture seule** (`?past=` jours, défaut 3 ; `?future=`, défaut 45) ; évènements ménage avec `cleaningId` |
| GET | `/api/place-links` | PMS_MANAGE : vue d'ensemble des liaisons logement ↔ lieu `{demo, placeFrontUrl, error, places[], properties: [{id, name, lodgifyPropertyId, placeId, placeName, status: linked\|unlinked\|missing\|unreachable, counts: {locks, upcomingGrants, openCleanings, lowStock}}]}` (ménages lus dans Rocket Clean, stock dans Rocket Stock) ; `placeFrontUrl` = `ROCKET_PLACE_FRONT_URL` |
| GET | `/api/properties/{id}/cleanings` | PMS_MANAGE : ménages du lieu (Rocket Clean) |
| GET | `/api/properties/{id}/cleanings/{cleaningId}/link` | PMS_MANAGE : lien secret sans compte pour l'agent de ménage `{url, path, expiresAt}` (404 si le ménage n'est pas de ce lieu) |

Sans lieu lié, les routes relayées répondent **409**. Une application agissant pour elle-même (Bearer `rpm_…` sans impersonation) peut appeler toutes ces routes métier, dont `POST /api/planning/run` et les liens ménage.

## Ménage (Rocket Clean)
PMS appelle Rocket Clean (`ROCKET_CLEAN_URL`/`ROCKET_CLEAN_TOKEN`, mêmes chemins que l'ancien ménage de Rocket Place) : `GET /api/places/{placeId}/cleanings`, `POST /api/places/{placeId}/cleanings` `{scheduledAt, dueAt?, label?, notes?, externalRef, type: "rental", origin: "pms"}` (idempotent par `externalRef` = `booking:<id>:checkout`, 201/200), `PATCH /api/cleanings/{id}` (`scheduledAt`/`dueAt`, ou `status: cancelled`). Lien du ménage : `GET /api/cleanings/{id}/link`. À chaque planification, les séjours du logement sont poussés comme **occupation** : `PUT /api/places/{placeId}/occupancy` `[{from, until, externalRef: "booking:<id>"}]` (Rocket Clean signale les ménages personnels ou d'entretien prévus pendant un séjour). Les tâches sont créées par la planification (tâche récurrente `RunPlanning` toutes les 15 min, ou `POST /api/planning/run`), jamais par une lecture ; elles apparaissent dans la timeline (`kind: cleaning`).
